# Release Year Prediction: ML Model to Flask to Angular to GitHub CI/CD

A teaching and research prototype. A trained LightGBM regression model (YearPredictionMSD) is
packaged as a scikit-learn pipeline, served by a Flask REST API, used through an Angular form,
and published with GitHub Actions and GitHub Pages. This follows the Week 6 DevOps lab manual
*From a Trained ML Model to a Full-Stack Research Application*.

- GitHub repository: `https://github.com/YOUR_USERNAME/YOUR_REPO` (fill in after Stage 12)
- GitHub Pages (static demo only): `https://YOUR_USERNAME.github.io/YOUR_REPO/` (fill in after Stage 14)

## 1. Problem and task

Predict the release year of a song from 90 audio timbre features. This is a **regression** task:
the API returns one number (the predicted year), not class probabilities.

## 2. Model provenance

- Trained by the author in `notebooks/YearPredictionMSD_Paper_Reproduction.ipynb` (sections 14 to 19).
- Data: YearPredictionMSD (UCI Machine Learning Repository), 515,345 songs, 91 columns (`Year` plus 90 features).
- Split: the dataset's official order-based split, first 463,715 rows for training and the last
  51,630 rows for testing. No shuffling, because songs by the same artist are stored together.
- Model: LightGBM regressor (`num_leaves=12`, 1000 rounds, learning rate 0.1) inside a
  scikit-learn `Pipeline` (identity preprocessing step, then the model). Tree models need no scaling.
- Test performance: MSE 80.63, R-squared 0.3153, RMSE about 9 years. This is a rough estimate,
  not a precise date. For the example record in `data/sample_inputs.csv` the model predicts about
  1992 while the true year is 2007, which is a typical size of error.
- Saved artifact: `backend/models/model_bundle.joblib` (a dictionary with the fitted `pipeline`,
  the ordered `features` list, `task`, `model_version`, `target` and `metrics`). Only load model
  files you created yourself.

## 3. Features (input schema)

90 numeric inputs, in this exact order: `TimbreAvg1` to `TimbreAvg12` (timbre averages) and
`TimbreCovariance1` to `TimbreCovariance78` (timbre covariances). The full list with the allowed
numeric ranges is in `frontend/src/app/feature-schema.ts`, generated by the training notebook.
There are no categorical inputs.

## 4. Versions used

- Python 3.12 (see `backend/requirements.txt` for exact package versions)
- Node.js 24 LTS, npm 11, Angular CLI 22.2
- The model file must be loaded with the same scikit-learn and LightGBM versions it was saved with.

## 6. Installation (Windows PowerShell, from the project root)

```
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt

cd frontend
npm install
cd ..
```

If PowerShell blocks the activation script, run
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned` and try again.

## 7. Run locally (three terminals)

Terminal 1, Flask (leave it running):

```
cd <project root>
.\.venv\Scripts\Activate.ps1
python backend\app.py
```

Terminal 2, Angular (leave it running):

```
cd <project root>\frontend
npx ng serve --open --proxy-config proxy.conf.json
```

Terminal 3, commands, tests and Git. Open http://localhost:4200, click **Fill sample record**,
then **Run local prediction**. The browser calls `/api/predict`, and the Angular dev proxy
forwards it to Flask at `http://127.0.0.1:5000/predict`.

## 8. Tests

From the project root with the virtual environment active:

```
python backend\make_payload.py
python backend\test_pipeline.py
python -m pytest -q backend\tests
```

Expected: `PASS: local inference` and 8 passed (the manual's 4 API tests, 3 extra validation
tests, and 1 structure test). With Flask running you can also run `python backend\test_api.py`
and `curl.exe --noproxy "*" -i http://127.0.0.1:5000/health`.

Frontend:

```
cd frontend
npm run build
npx ng test --watch=false
```

## 9. Retraining the model

Open `notebooks/YearPredictionMSD_Paper_Reproduction.ipynb`, put `YearPredictionMSD.csv` in `data/`,
run the setup, loading and split cells (sections 1 to 4), then sections 14 to 19. They rewrite
`backend/models/model_bundle.joblib`, `data/sample_inputs.csv`, `backend/test_payload.json` and the
Angular feature schema. The whole notebook (all four models) takes a long time on a laptop;
the lab sections only need the first four sections.

## 10. Continuous integration and deployment

- `ci.yml` installs the Python requirements, runs all backend tests (the model bundle and sample
  payload are committed, so the model tests run in CI), then builds the Angular app and uploads
  it as an artifact.
- `pages.yml` builds Angular with the repository name as the base path and publishes
  `frontend/dist/frontend/browser` to GitHub Pages. In GitHub, set Settings > Pages > Source to
  **GitHub Actions** once.

## 11. Deployment limitations

GitHub Pages hosts **only the static Angular interface**. It does not run Flask, the model, or any
Python. On the public site the form renders but the prediction button is disabled and a notice
explains why. Live public predictions would need a separately hosted, secured backend with an
HTTPS API; that is not part of this project.

## 12. Notes on the Angular code

The generated Angular 22 app is zoneless, so the component keeps `loading`, `error` and `result`
in signals. Plain fields would not refresh the screen after the HTTP response arrives. The form
also has a **Fill sample record** button, because typing 90 values by hand is impractical.

## 13. Research and ethics disclaimer

Research and teaching prototype only. The prediction is a statistical estimate of a song's release
year from audio timbre statistics and can be wrong by many years. Do not use it for decisions.
The dataset is a public research dataset and contains no personal information.
